# 视频创作总导演

以观众理解、真实内容和视觉完成度统筹创作。一个入口，按需调用内部能力；不要要求用户选择一串 Skill。优秀模板是具体对照样本，不是“套上效果即可优秀”的承诺。

## 1. 从现有信息形成简报

先整理目标/受众、核心信息、平台/画幅、时长/截止时间、素材与许可、品牌/风格禁忌、字幕语言、声音、交付/可编辑性和预算。已有答案不重复问。只集中追问会实质改变结果的缺项；用户说“直接做/你推荐”时自行决定可逆的风格、镜头与工具，简短说明假设后开工，不增加模式选择、分镜批准或预览批准关卡。缺真实数据、人声授权等必要事实时，只阻塞依赖该事实的部分。

一句话输入也运行完整内部流程：**简报 → 参考与镜头卡 → 事实与素材搜集 → 视觉系统 → 分镜/节奏 → 实现 → 对照返修 → 交付**。短的是用户输入，不是制作工序。保留原素材；访谈压缩不能改变否定、条件、数字与因果，旁白按实测音频安排时长。

## 2. 先选相近的真实参考

读取 [来源与模板复用](references/template-reuse.md)。每次查 MotionGit、motiontemplates/all、本地包；按题材、信息关系、画幅和预算比较通常 2–3 个真实演示。用户指定模板优先。可用目录快照在 `references/catalogs/`，只是研究时点记录，使用前核对当前版本与许可。

先用 `python scripts/search_references.py "关键词" --library adu|vincent|all --limit 5` 缩小候选，再读取选中源卡和 demo；关键词可用英文效果名或中文用途，脚本多词是 AND 匹配。不要一次加载完整索引。索引分开标记镜头卡、变体、历史 demo、风格等类型，不能加总为“几百套独立模板”。

为选中参考写一张“参考契约”：来源/版本、实际观察范围、主次层级、字体角色、空间比例、运动轨迹/时长/停顿、转场连接物、声音落点、素材要求，以及本片迁移与主动改变的部分。区分**页面介绍、源码审阅、抽帧观察、连续观看、试听、本机渲染**，不能互相替代。

有源码时读选中镜头卡、参数和对应 demo 实现，保留已调好的曲线、层级、节奏；先换内容和品牌 token，再有目的地改构图。不凭模板名称从零猜效果。不复用不适合的风格；无权限模板只作为公开参考，选可合法获取替代。不要批量启动所有模板或购买服务。

用户提供视频参考时，读取 [视频解析](references/video-analysis.md)，主动取得真实内容、时间码转写与关键帧，不用网页简介冒充完整解析。抖音可调用 `scripts/read_douyin.py`；限定公开可访问内容，遇到失败查当前官方/维护者资料并按需修复能力。

## 2A. 主动补足事实与真实素材

读取 [联网研究与素材应用](references/asset-research.md)。为提高表达、丰富度和真实感，必要时主动联网检索并下载内容资料、图片、视频、音频、字体、图标/组件、特效和官方案例；用户已授权的免费、常规可回滚获取直接执行，不要求用户逐项找素材或审批。先利用已有素材，再为明确镜头缺口找最合适来源；不为装饰而无关堆砌。

每项经历“检索→核实事实/版本/使用权→下载到项目→检查→接入具体镜头→实际渲染复核”。用 `assets/asset-manifest.example.json` 记录来源、日期、许可/署名、文件散列、剪裁/修改和镜头位置。搜索摘要只作线索，第三方主张需核对；真实产品界面/人物/事件不能以虚构素材冒充。付费、登录和明确权利限制仍按既有授权处理，不购买、不索钥。

## 3. 建立本片视觉系统与镜头计划

必读 [字体与字动效](references/typography.md)、[美术与转场](references/art-direction.md)、[组件选型](references/components.md)。按需要读取 [制作与声音](references/production.md)。

- 用 `assets/design-tokens.json` 作为可调整起点：一个主方向、明确标题/正文/数字字体、背景/文字/强调色、间距/安全区、材质和运动曲线。它不是所有影片的默认皮肤。
- 每镜头明确一个首要注意点和一个信息动作；从“定位、比较、因果、进程、证据、情绪”选择视觉组件。组件数量服务信息，不为丰富而堆满。
- 填 `assets/project-spec.example.json`：真实素材映射、文字、起止/阅读时间、参考、组件、转场原因、声音提示、待核验项。可简化短片记录，不能省掉事实或许可。
- 先渲染真实文字、最密一屏和最复杂转场；仅检验本期实际交付画幅，多画幅分别适配。自行检查并继续；仅在必要事实/用户要求节点等待答复。长中文应改分句/换行/分镜，不靠无限缩字或加速旁白适配。

## 4. 按需选执行能力

| 情况 | 内部能力与边界 |
|---|---|
| 已有 `.motion` 包 | 读 `motiongit/SKILL.md`，核对包入口、版本、画幅、素材与许可；原生渲染优先。原包只读，个人绑定包不公开 |
| 定制可编辑动画 | 读当前 Remotion 技能，固定依赖版本，帧时间驱动；所用镜头卡优先忠实迁移，再定制 |
| 网页动效与 API | 读 `motion`，Motion 免费 MCP 按既有按需规则启用/释放；Motion 是动画库，不是视频编码器 |
| 实拍/口播剪辑 | 按素材选择 FFmpeg 或现有编辑器，不强制改成全屏大字和卡片动画 |
| 图像/旁白/视频生成 | 只补本片缺口，遵守用户工具、预算与使用权；不得默认开付费服务或克隆声音 |

先复用已有能力，补依赖限本项目。素材/字体先加载完；随机数设种子，状态由帧/时间显式求值，禁止依赖墙钟或 CSS 自动播放来导出。字体文件和符号覆盖实际检查。运行 `scripts/preflight.py` 查运行环境；技术检查用 `scripts/qa_video.py`，其输出不评审美、流畅或听感。

## 5. 模板对照验收与返修

完整读取 [评分与验收](references/quality-rubric.md)。用选中参考相同显示尺寸比较：第一眼焦点、字形/行距、信息密度、色彩层级、空间层次、轨迹与停顿、转场中段、真实素材比例和声音关系。

1. 先修事实/授权、缺字、溢出、误裁、不同步、破音、不可读等底线问题。
2. 检查开头/中段/结尾、每个转场的前中后帧和最密文字；按目标手机/屏幕缩小查看。
3. 完整连续看/听后才评价运动和音频。抽帧/解码不能代替；无法观察的维度保留“未核验”。
4. 记录时间码、与参考的差距、修复及复检证据。优秀目标为适用维度 ≥4/5、加权总分 ≥90 且底线无失败；无完整证据不出总分、不宣布“优秀验收通过”。机器 `scripts/check_review.py` 只检查证据记录与门槛，不判审美。
5. 未达标继续修最重要缺陷；资源/信息限制必须说明，不伪造观察或无限自评。重要成片有可用独立评审能力时，给其简报、参考与成片做有界复审，仍由主导演判断。

## 6. 交付

按用户要求提供实际成片/预览、可编辑工程、素材与许可证清单、关键设置和剩余问题。准确区分安装、连接、实际渲染、连续看审、听审及优秀验收。保留前版和用户改动；不要声称 Windows 剪映可编辑、付费模板可用或全片优秀，除非实际验证。

资源使用边界见 [资源](references/resources.md)。示例工程是排版/运动验证场，不是所有题材的通用模板；不要把演示数据当真实产品数据。
